## 这份文档讲什么

这份文档详细介绍 Galgame 界面中每一个功能模块是什么、怎么用、以及按下按钮后游戏内部发生了什么。文档面向普通玩家，不要求你懂代码。

## 一、界面整体布局

打开 Galgame 界面后，屏幕上的元素从上到下分为以下几层：

```
┌─────────────────────────────────────────────────┐
│              舞台区域（最底层）                    │
│   背景图片 │ 弹幕飘字 │ 角色立绘 │ 视觉特效          │
├─────────────────────────────────────────────────┤
│              图片卡牌队列（中间层）                │
│              扇形排列的历史图片卡牌                  │
├─────────────────────────────────────────────────┤
│  左上按钮 │ 成就徽章（居中）│ 右上按钮   （顶层）   │
│  对话框（含导航）│ 选项面板│ 各功能子面板（叠加层）   │
└─────────────────────────────────────────────────┘
```

### 各区域说明

- **舞台区域**：显示背景图片、角色立绘、弹幕和视觉特效
- **图片卡牌队列**：以扇形排列的方式展示之前生成的背景/CG 图片
- **左上/右上按钮**：快速访问各种功能的快捷入口
- **对话框**：显示当前角色的对话台词和旁白
- **选项面板**：玩家做出选择的地方
- **各功能子面板**：商店、2048、废土行路等玩法面板，点击后覆盖在对话框上方

## 二、对话框系统

### 2.1 对话框是什么

对话框是显示在屏幕底部的区域，用于呈现角色的台词和旁白描述。

对话框有三种样式：

| 样式 | 什么时候出现 | 文字颜色 | 特点 |
|------|------------|---------|------|
| **普通对话** | 角色说话时 | 报纸风格色 | 正常显示 |
| **心理描写** | 角色内心独白时 | 纯黑色 | 加粗，更深沉 |
| **黑屏文字** | 旁白/环境描述 | 白色 | 覆盖全屏，深色背景 |

### 2.2 对话框各部分功能

```
┌─────────────────────────────────────────────────┐
│  [◀]  [▶] 角色名：台词内容...      [🔊] [⏸]     │
│         打字机效果区域                              │
│              [跳过] [自动播放]                     │
└─────────────────────────────────────────────────┘
```

- **角色名标签**：显示当前说话的角色名称（也可能是"旁白"或"????"）
- **打字机效果**：台词会一个字一个字地出现，有打字音效（如果有的话）
- **跳过按钮**：立即显示当前段落全部文字，跳到下一段
- **自动播放按钮**：开启后，打字结束后自动播放下一句（无需点击）
- **朗读按钮**：点击后尝试朗读当前台词（需要浏览器支持语音功能）
- **导航箭头**：`◀` 返回上一句，`▶` 前进到下一句

### 2.3 点击或按键操作

| 操作 | 效果 |
|------|------|
| 点击对话框 | 立即完成当前打字效果，显示全部文字 |
| 按 `空格` 键 | 同上 |
| 按 `→` 右箭头 | 前进到下一句 |
| 按 `←` 左箭头 | 返回上一句 |
| 按 `Ctrl + →` | 前进到下一个角色发言块 |
| 按 `Ctrl + ←` | 返回上一个角色发言块 |
| 按 `Esc` 键 | 关闭当前打开的面板（如商店、2048） |
| 打字过程中点击 | 取消打字效果，直接显示全文 |

### 2.4 剧情消息格式（高级）

在消息中使用以下标签可以控制游戏行为：

| 标签 | 作用 | 示例 |
|------|------|------|
| `<content>...</content>` | 包裹所有剧情文本 | `<content>角色A：你好...</content>` |
| `<dm>...</dm>` | 弹幕标签，生成 AI 弹幕 | `<dm>好耶</dm><dm>刀</dm>` |
| `<background>背景名</background>` | 切换背景图片 | `<background>废墟城市</background>` |
| `<image>图片名</image>` | 显示 CG 图 | `<image>废墟城市_夜</image>` |
| `[[character\|\|角色名\|\|台词]]` | 普通对话 | `[[character\|\|艾琳\|\|今天天气真好。]]` |
| `[[narration\|\|旁白内容]]` | 旁白描述 | `[[narration\|\|夜幕降临了。]]` |
| `[[blacktext\|\|黑屏文字]]` | 黑屏文字（覆盖全屏） | `[[blacktext\|\|时间回到三年前……]]` |
| `[[choice\|\|选项1::内容1::金币1]]` | 选项标签 | `[[choice\|\|搜索房间::+0::0]]` |

## 三、角色系统

### 3.1 角色是什么

Galgame 中的角色是指在对话中出现的人物。角色可以是 AI 生成的角色（通过对话），也可以是玩家自己（玩家类型的角色）。

### 3.2 角色立绘

当剧情中提到某个角色时，游戏会尝试在世界书中查找该角色的立绘图片，并在屏幕下方显示该角色的形象。

**立绘显示位置**：默认为右对齐（角色站在右侧），可以在设置中调整为左对齐或居中。

### 3.3 成就关联

部分成就会与特定角色关联。当你与某个角色进行互动时，该角色的相关成就会从"未标记"状态变为"进行中"。完成特定条件后，成就变为"已完成"。

## 四、弹幕系统

### 4.1 弹幕是什么

弹幕是指从屏幕右侧飘入、左侧飘出的评论文字，模拟视频网站弹幕效果。弹幕内容由 AI 自动生成，也可以是手动配置的固定弹幕。

### 4.2 弹幕怎么生成

有两种方式触发弹幕：

**方式一：AI 自动生成**
1. AI 生成剧情完成
2. 系统提取对话内容
3. 调用第二 API 生成弹幕（如果有配置的话）
4. 弹幕以随机间隔依次飘出

**方式二：手动配置**
在消息中使用 `<dm>...</dm>` 标签手动指定弹幕内容。

### 4.3 弹幕配置

在设置面板中配置弹幕：

| 配置项 | 作用 |
|--------|------|
| **弹幕开关** | 开启/关闭弹幕显示 |
| **弹幕速度** | 控制弹幕飘过的速度（快/中/慢） |
| **弹幕循环** | 开启后，同一批弹幕会循环播放 |
| **显示区域** | 屏幕上半部分 / 屏幕下半部分 / 全屏 |
| **字体大小** | 调整弹幕文字大小 |
| **弹幕颜色** | 所有弹幕统一颜色，或使用随机彩虹色 |
| **透明度** | 弹幕背景的透明度 |

## 五、图片系统

### 5.1 图片生成流程

当剧情中提到场景变化时，系统会自动尝试生成对应的背景或 CG 图片。

**完整流程**：

```
AI 生成剧情消息
    ↓
系统解析消息，检测场景变化标记
    ↓
根据标记判断生成背景图还是 CG 图
    ↓
生成图片标签（AI 自动生成 或 使用世界书预设标签）
    ↓
将标签发送给外部生图插件（SD WebUI / NovelAI 等）
    ↓
插件返回生成的图片
    ↓
在舞台上显示新图片
    ↓
同时将图片添加到扇形卡牌队列中
```

### 5.2 图片卡牌队列

屏幕中央以扇形排列的卡牌就是图片卡牌队列。每次生成新图片时，新卡牌会从扇形底部展开，卡片中央显示缩略图。

**点击卡牌**：放大显示完整图片，可以关闭。
**卡牌数量上限**：最多保存 5 张历史图片，超过后最早的卡牌会消失。

### 5.3 图片生图重试

如果生成的图片不满意，可以：

1. 点击卡牌放大图片
2. 点击右上角的"重新生成"按钮
3. 在弹出的面板中选择：
   - **仅重发生图标签**：不更换描述，只重新生成图片
   - **重新生成标签和图片**：更换描述，重新生成
4. 点击确认后，系统重新调用生图插件

> **注意**：重试会额外消耗生图插件的配额。

### 5.4 图片生图失败的处理

系统有三级降级机制：

```
优先使用 → 第二 API 生成标签 → 第一 API 生成标签 → 禁用图片生成
```

- 如果第二 API 生成失败，自动降级到主 API
- 如果主 API 也失败，图片功能暂时不可用
- 降级过程不会影响剧情生成

## 六、世界书系统

### 6.1 世界书是什么

世界书（Worldbook）是酒馆助手中的一个功能，允许你为游戏定义各种资源、背景设定、角色信息等。Galgame 界面会读取世界书中的条目来丰富游戏体验。

### 6.2 Galgame 识别的世界书条目

| 条目类型 | 在世界书中的形式 | 作用 |
|----------|----------------|------|
| **背景图片** | JSON 格式，key 为图片名称 | 提供背景图片 |
| **CG 图片** | JSON 格式，key 为 CG 名称 | 提供 CG 图片 |
| **角色立绘** | JSON 格式，key 为角色名 | 提供角色立绘 |
| **成就列表** | JSON 格式，key 为 "成就列表" | 定义所有成就 |
| **末世通讯联系人** | JSON 格式，key 为联系人名称 | 定义系统聊天人格 |

### 6.3 背景图片条目格式

```json
{
  "废墟城市": {
    "tags": ["post-apocalyptic", "ruins", "city", "night"],
    "priority": 10
  }
}
```

- `废墟城市`：图片的唯一名称
- `tags`：用于模糊匹配的关键词
- `priority`：优先级，数字越大越优先匹配

### 6.4 CG 图片条目格式

```json
{
  "废墟城市_夜": {
    "tags": ["post-apocalyptic", "ruins", "night scene"],
    "prompt": "highly detailed CG..."
  }
}
```

- `废墟城市_夜`：CG 的唯一名称
- `tags`：模糊匹配关键词
- `prompt`：可选，高质量图片生成提示词

### 6.5 角色立绘条目格式

```json
{
  "艾琳": {
    "image": "ailin_sprite",
    "tags": ["girl", "blonde", "adventurer"]
  }
}
```

- `艾琳`：角色名称
- `image`：立绘图片名称
- `tags`：用于模糊匹配的关键词

### 6.6 模糊匹配原理

当剧情中提到一个名称时，系统会检查所有世界书条目，找出名字或标签与提到内容最接近的条目并使用它。

例如，剧情中提到 `[[character||艾琳||废墟中醒来]]`，系统会查找包含"艾琳"或相关标签的世界书条目，找到后显示对应的角色立绘。

## 七、成就系统

### 7.1 成就怎么显示

屏幕顶部中央有一个小徽章图标。初始只显示图标，鼠标悬停后展开为一个半透明面板。

### 7.2 成就分类

成就分为两类：

| 类型 | 状态数 | 说明 |
|------|--------|------|
| **通用成就** | 未标记 / 已完成 | 不绑定特定角色 |
| **角色成就** | 未标记 / 进行中 / 已完成 | 与特定角色相关 |

### 7.3 成就条件追踪

成就的"进行中"状态根据以下条件自动切换：

- **世界崩溃度**：一个全局数值，影响部分成就的显示
- **当前场景**：根据背景图片名称判断当前场景
- **当前角色**：根据对话中出现的角色名称判断

### 7.4 成就列表条目格式

世界书中名为"成就列表"的条目格式：

```json
[
  {
    "id": "achieve_001",
    "name": "初入废土",
    "description": "第一次在废墟中醒来",
    "condition": {
      "type": "stage",
      "value": "废墟"
    }
  },
  {
    "id": "achieve_002",
    "name": "与艾琳的羁绊",
    "description": "与艾琳完成一次完整的对话",
    "condition": {
      "type": "character",
      "value": "艾琳",
      "stage": 2
    }
  }
]
```

## 八、存档系统

### 8.1 存档原理

Galgame 界面不提供独立的存档按钮。游戏数据自动保存在酒馆聊天变量中：

| 数据类型 | 保存位置 |
|----------|----------|
| **设置数据** | 浏览器 localStorage（`vn_galgame_settings`） |
| **游戏数据** | 酒馆聊天变量（`vn_game`） |

这意味着只要你使用同一个聊天文件，游戏进度就不会丢失。

### 8.2 游戏数据包括什么

`vn_game` 变量中保存了以下数据：

- 金币数量
- 背包物品
- 各个玩法的进度（商店已购物品、生产线等级等）
- 成就完成状态
- 历史消息

### 8.3 重置游戏

如果你想重新开始游戏，需要清除聊天变量中的 `vn_game` 数据（在世界书管理中删除该变量）。

> **注意**：这会清除所有游戏进度，包括金币、物品和成就。

## 十一、内置流程详解

### 11.1 AI 生成消息的完整流程

```
用户发送消息（或点击生成）
    ↓
酒馆系统调用主 AI 生成剧情
    ↓
AI 逐 token 流式输出到聊天楼层
    ↓
[Galgame 监听] 检测到 STREAM_TOKEN_RECEIVED
    ↓
流式文本在对话框中逐字显示（打字机效果）
    ↓
AI 生成完毕，触发 GENERATION_ENDED 事件
    ↓
[triggerDanmakuAndImageGen] 解析消息内容
    ↓
├─ 提取 <content> 标签 → 推送弹幕（如果配置了）
    │
├─ 提取场景标记 → 准备生成图片
    │
├─ 如果同时需要弹幕和图片 → 一次 API 调用获取两者
    │
└─ 如果分开配置 → 分别调用 API
    ↓
弹幕在屏幕上飘动
图片生成后显示在舞台和卡牌队列中
```

### 11.2 消息解析流程

`utils/messageParser.ts` 中的 `parseMessageBlocks` 函数负责将原始文本转换为可显示的结构：

```
原始消息文本
    ↓
提取 <content> 标签内的内容
    ↓
处理 [[character||名字||台词]] 格式
    ↓
处理 [[narration||旁白]] 格式
    ↓
处理 [[blacktext||黑屏文字]] 格式
    ↓
处理 [[choice||选项]] 格式
    ↓
处理换行符（每段话一个 block）
    ↓
模糊匹配世界书资源（背景、立绘等）
    ↓
返回 MessageBlock[] 数组
    ↓
Vue 组件渲染显示
```

### 11.3 图片生成流程（详细）

```
剧情中出现场景标记（如 [[character||艾琳||场景：废墟城市]]）
    ↓
parseMessageBlocks 解析消息，识别到场景标记
    ↓
extractImageTagBlocks 提取所有图片标记
    ↓
判断标记类型：
  ├─ <background> → 生成背景图
  ├─ <image> 或 CG 标记 → 生成 CG 图
  └─ 标题类标记 → 生成对应场景图
    ↓
检测是否已配置生图标签：
  ├─ 有预设标签（世界书）→ 直接使用
  └─ 无预设标签 → 调用第二 API 生成标签
    ↓
将标签发送给外部生图插件
    ↓
等待插件返回图片
    ↓
[imageCardQueue] 创建新卡牌，加入扇形队列
    ↓
[StageArea] 更新舞台背景
    ↓
显示完成提示
```

## 十二、技术架构说明（可选阅读）

> 这一节面向对技术感兴趣的读者，普通玩家可以跳过。

### 12.1 核心技术栈

| 技术 | 作用 |
|------|------|
| **Vue 3** | 界面渲染框架 |
| **Pinia** | 状态管理 |
| **Tailwind CSS** | 样式框架 |

### 12.4 数据流

```

    ↓
Pinia Store（VNStore）管理状态
    ↓

    ↓
玩家交互 → Store 方法 → 酒馆变量持久化
```
