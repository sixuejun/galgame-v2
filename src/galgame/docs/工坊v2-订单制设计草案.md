# 工坊 v2：订单制（草案）

> 目标：把"工坊挂机"升级为"订单驱动 + 短时反馈 + 角色参与 + 可扩展状态机"的玩法模块。
>
> 本文是设计/规划文档（协议与数据结构导向），不是实现细节。
>
> 关键约束（已确认）：
>
> - 订单为**单角色**执行。
> - 订单时长为真实等待（类似当前工坊运作方式）。
> - 主要收益以**金币**为主。
> - 多个角色同时在工坊工作时：高 `社交` 角色会对**所有订单**提供加成（"车间氛围"）。
> - `逃班/加班/疲劳` 会影响角色**长期状态**。
> - 工坊日志以"弹幕"形式随机滚动播放，并对生产产生**实时影响**。

---

## 0. 术语

- **订单定义（OrderDef）**：一条可接取的订单模板；AI 只负责生成 `workType/title/brief/tags` 等风味字段，`requirements/reward/durationSec` 等数值与规则由系统随机/计算。
- **订单实例（OrderRun）**：一次订单执行过程（运行态），只保存必要的持久状态（例如：指派角色、开始时刻、累计收益/累计秒数、是否加班等）；进度与收益由"开始时刻 + 累计秒数 + 当前倍速"实时推导。
- **Tick（弹幕日志）**：订单运行中周期触发的弹幕句子，会以"随机增减已积累秒数（progressSec）"的方式即时影响进度与收益。tick 不要求记录时间戳与事件 id，作为可清空的展示列表即可。
- **车间氛围（Workshop Aura）**：多个角色同时在工坊工作时产生的全局倍速效果，主要由 `社交` 贡献；更像是对所有正在运行订单叠加一个 `auraSpeedMul`。

---

## 1. 玩法循环（高层）

1. **刷新/生成订单库**：从第二 API 生成一批订单文案字段（6~12 条），系统补全 `orderId`、并按规则随机/计算 `requirements/reward/durationSec` 等数值，写入聊天变量。
2. 玩家选择一条订单 + 指派一个角色执行，创建对应 `OrderRun`（只保存开始时刻与累计量）。
3. 订单运行期间：

- 基础速度加成：在**订单开始时**一次性计算（来自角色属性，技能 mod、订单 requirements 等）。
- 全局倍速：由"车间氛围（社交）"提供，可在订单进行中动态变化。
- 弹幕 tick：周期触发，使用"随机增减已积累秒数（progressSec）"的方式即时改变进度与收益。

4. 中断/停止/完成：

- 若中断或手动停止：收益按当前进度条比例结算。
- 若触发加班：允许进度超过 100%，超出部分按同规则折算额外收益。
- 结算后回写角色长期状态（疲劳/休息/逃班冷却等），并追加工坊日志。

5. 订单实例结束并归档；工坊没有任何工作时可自动清空弹幕列表（用户也可手动清除）。

## 2. 数据模型（建议，尽量少变量）

> 变量存储建议：优先聊天变量 `{type:'chat'}`。

> 说明：为了让你更好把控复杂度，这里把字段拆成"必须存的"和"可以推导不存的"。

### 2.1 订单定义（订单库里的每条订单）

AI 生成字段（只负责文案）：

- `工种`：冶炼/制药/改装
- `标题`
- `说明`
- `标签[]`

系统补全字段（数值与规则）：

- `订单id`
- `订单时长秒`（60~300 完全随机）
- `基础金币`（系统随机）
- `偏好`（用于开局倍速）：
  - `偏好属性[]`（如 技巧/谨慎/智慧）
  - `偏好阈值`（如 >=3）
  - `满足偏好时的开局倍速加成`

### 2.2 订单实例（进行中订单，运行态）

必须存（跨会话恢复所需）：

- `订单id`
- `角色id`
- `开始时间戳`
- `进度秒`（会被 tick 随机增减）
- `订单内疲劳`
- `加班中`（是否允许进度超过 100%）

可选存（能推导就不存）：

- `开局倍速`：
  - 若开局倍速包含随机成分，建议存；
  - 若完全可重复计算（只依赖订单/角色/技能），可以不存。

不建议存（动态、可实时计算）：

- `车间倍速`：由当前所有在工坊工作的角色（社交）实时算出来即可。

### 2.3 工坊弹幕（纯展示）

- `弹幕[]`：只存字符串数组即可。

不存：

- tick 时间戳
- tick 事件 id
- 每单 tick 上限

### 2.3 Tick（弹幕）

tick 本质上就是：

- 往 `弹幕[]` 里追加一句文本
- 同时对当前订单做一次影响（主要是 `进度秒 += 增减秒`）

因此不需要：

- tick 时间戳
- tick 事件 id
- 复杂结构化 effects

---

### 2.4 车间氛围（社交全局倍速）

你确认它更像"同时在工作的所有订单都加了一个倍速效果"。建议口径：

- `车间倍速` 是一个实时计算值，不必落盘：
  - 输入：当前所有正在工坊工作的角色的 `社交`
  - 输出：一个倍速系数（例如 1.00 ~ 1.30）

> 这里也不强制引入复杂变量名（如 `activeRoleIds/auraMods`）。只要你能在实现里算出"一个全局倍速"，并且它能随工坊里角色数量变化而变化即可。

## 3. 与角色系统的接口（Runtime/Logs）

### 3.1 角色运行态（Runtime）扩展建议

你在 `玩法-角色与派遣规划.md` 已规划 Runtime 枚举：`工坊中/逃跑中/休息中/加班中` 等。

### 3.2 结算回写规则（建议，按"少变量"原则）

订单结束（成功/失败/中断结算）时：

1. **金币入账**：按进度条比例结算金币（见第 7 节）。
2. **疲劳（只在本单内）**：
   - tick 可以增加 `订单内疲劳`
   - 若 `订单内疲劳` 达到阈值（例如 3）：强制下班（结束订单并结算收益），并把 `角色当前状态 = 休息中`
   - 若订单结束时 `订单内疲劳` 未达到阈值：不保留、不写回角色（等价于清空）
3. **逃班/事故回写**（若发生）：
   - 把 `角色当前状态 = 逃跑中` 或 `受伤/异常`（按你角色系统已有的状态字段即可）
4. **记录追加**：往角色的工坊记录里追加一条摘要（订单标题、结果、金币变化）。

## 4. 弹幕 tick 的作用方式

你确认的规则（尽量用中文口径）：

- 弹幕 tick 对订单的影响方式是：**随机增减"已积累的进度秒数"**。
  - 文中把这个值称为 `进度秒`（对应代码里你可用 `progressSec` 之类命名）。
- 其它所有"速度加成"（角色偏好，技能、订单偏好）都在**订单开始时一次性计算**为"开局倍速"。
  - 文中称为 `开局倍速`（可对应 `baseSpeedMul`）。
- 车间氛围（社交）是运行中动态的：更像给所有正在进行的订单叠加一个"车间倍速"。
  - 文中称为 `车间倍速`（可对应 `auraSpeedMul`）。

### 4.1 tick 增减进度秒（示例规则）

tick 触发后：抽一个 `增减秒`，并直接作用到 `进度秒`。

- 常规订单：`增减秒 ∈ [-3, +6]`（正向偏多）
- 危险/事故倾向订单：`增减秒 ∈ [-8, +4]`（负向偏多）

应用：

- `进度秒 = clamp(进度秒 + 增减秒, 0, 上限)`
- 上限：
  - 非加班：上限建议 = `订单时长秒`
  - 加班：允许超过 `订单时长秒`

> 这样不需要记录 tick 的时间戳、事件 id：tick 只要做两件事即可：
>
> 1) 改变 `进度秒`
> 2) 往弹幕列表 push 一句文本

### 4.2 中断/停止时的收益计算

- 若订单途中中断（玩家手动停止、切换角色、关闭模块等）：
  - `进度比例 = 进度秒 / 订单时长秒`
  - `金币 = floor(基础金币 * 进度比例)`
- 若加班允许超出进度条：
  - `进度比例 = 进度秒 / 订单时长秒`（允许 > 1）
  - `金币 = floor(基础金币 * 进度比例)`

> 你提到"加班永动机基本不存在"，因为疲劳会强制下班。
> 因此这里不强制写死倍率封顶。

## 5. Tick（弹幕日志）细化：句子类型与倾向

> 目标：tick 既是氛围弹幕，也是"随机增减进度秒"的触发器。
>
> 设计原则：
>
> - 不要求记录 tick 的时间戳/事件 id；tick 只需要"往列表追加一条文本 + 改变进度秒/疲劳/状态"。
> - 不做每单 tick 上限：订单跑多久、tick 就滚多久（好玩优先）。
> - **tick 建议间隔：6~12 秒一条（随机）**。
> - **订单时长越长，"干涉"类 tick 概率越低**。

实现口径建议（你实现时任选其一）：

- 做一个"干涉权重衰减系数"，只作用于干涉类 tick：
  - 60~120 秒：系数 = 1.0
  - 120~240 秒：系数 = 0.6
  - 240~300 秒：系数 = 0.4

> 顺利推进/返工卡壳/轻微波动这类"口感 tick"可以不衰减，保证弹幕密度与可读性。

### 5.1 tick 的句子类型（建议 v1）

tick 可以分成几类，每一类都对应一个"进度秒增减范围"，并且会被属性/工种/tags 影响出现概率。

1) **顺利推进**（常见）
- 文案：正常工作、流程顺畅、工具趁手
- 效果：`增减秒` 偏正（例如 `+1 ~ +6`）
- 倾向：`技巧` 高更容易触发；`工坊等级`高更容易触发

2) **返工/卡壳**（常见）
- 文案：配比错了、零件不合、炉温飘了
- 效果：`增减秒` 偏负（例如 `-1 ~ -6`）
- 倾向：`谨慎` 高更不容易触发；危险 tag 更容易触发

3) **灵感/小优化**（较少）
- 文案：找到更快的工序、临时小改良
- 效果：一次性给较大的正向秒数（例如 `+5 ~ +12`）
- 倾向：`智慧`、`运气` 高更容易触发

4) **摸鱼/分心**（较少）
- 文案：走神、聊天、偷懒
- 效果：一次性给较大的负向秒数（例如 `-5 ~ -12`）
- 倾向：`社交` 高时更容易触发，类似"边聊边干活"

5) **加班**（可触发模式）
- 文案：主动加班、赶工、通宵
- 效果：
  - 开启/维持"允许超出进度条结算"的状态（加班模式）
  - 同时更容易触发疲劳增长
- 倾向：
  - `谨慎` 高时更容易触发

6) **疲劳上升**（重要，作为永动机上限）
- 文案：眼皮打架、手抖、嗓子哑了
- 效果：`疲劳 +1`
- 触发：
  - 订单持续越久越容易触发
  - 加班状态更容易触发

7) **逃班/事故**（稀有但有戏）
- 文案：
  - 逃班：`{name}逃跑了，本次订单失败`
  - 事故：爆炸/中毒/零件报废等
- 效果：直接失败、或大幅倒扣进度秒、或额外疲劳/受伤
- 倾向：`谨慎` 高显著降低；危险 tag 提高

> 你可以把每个类型理解为一个"模板池"。抽到类型后，从对应模板池里随机取一句。

### 5.2 tick 如何影响"加班收益"

- 加班模式开启后：允许 `进度比例 > 1`
- 进度比例越高，收益越高；但疲劳 tick 的概率也随之提高
- 因为疲劳会强制下班，所以"加班永动机"通常不会出现（自然上限来自疲劳）

## 6. 第二 API：订单库生成协议（建议）

### 6.1 设计原则（按最新约束调整）

- AI 负责：`workType/title/brief/tags`（订单文案与风味标签）
- 系统负责：
  - `orderId`
  - `durationSec`（60~300 完全随机）
  - `requirements`（偏好与开局速度加成规则）
  - `reward`（金币数值与封顶规则）

> 说明：`requirements/reward` 不让 AI 生成，可以显著降低经济失控与协议漂移成本。

### 6.2 协议（v1）建议

> Prompt 模板与解析器详见：`src/galgame/docs/工坊v2-订单生成Prompt设计.md`

```text
<workshop_orders_v1>
workType|title|brief|tags
冶炼|...
...
</workshop_orders_v1>
```

约束：

- 6~12 行
- 字段内禁止出现 `|`
- `workType` 必须是 `冶炼/制药/改装` 之一
- `tags` 用逗号分隔，可空

## 7. 结算（金币为主，按进度条比例）

你确认的规则：

- 订单途中中断：收益按进度条比例结算
- 若加班：收益允许按"超出进度条（>100%）的部分"继续结算

> 注：因为疲劳会强制下班，所以这里不默认添加复杂封顶。

### 7.1 结算输入（中文口径）

- `基础金币`
- `进度秒`
- `订单时长秒`
- `加班中`（是否允许进度比例 > 1）

### 7.2 结算公式（建议）

- `进度比例 = 进度秒 / 订单时长秒`
- 非加班：`进度比例 = clamp(进度比例, 0, 1)`
- 加班：允许 `进度比例 > 1`
- `金币 = floor(基础金币 * 进度比例)`

### 7.3 结算回写

- `金币`：入账
- `角色.疲劳 += 本单疲劳增量`；疲劳到阈值则把 `角色当前状态 = 休息中`
- 失败类 tick 触发失败时：把 `角色当前状态 = 逃跑中/异常`（按你的角色系统已有字段）
- 工坊弹幕：当工坊没有任何进行中的工作时，自动清空（玩家也可手动清空）
