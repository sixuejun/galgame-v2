# 工坊 v2：变量清单与清空机制（草案）

> 用途：把工坊订单制会用到的所有“状态变量”单独列出来，方便你逐个删减、改名、决定放哪。
>
> 设计目标：
>
>- 变量尽量少（能推导的不存）。
>- 不引入“休息时长 / 逃班冷却”这类时间戳变量（按你要求）。
>- 弹幕列表是纯展示，可手动清空；当工坊没有任何工作时自动清空。

---

## 1) 存储位置建议

### A. 聊天变量（存档/跨会话要保留）

- `工坊.订单库[]`：当前可接取订单列表（只存 AI 文案字段 + 系统补全字段）
- `工坊.进行中订单[]`：当前正在进行的订单实例列表（每条对应一个角色在干活）
- `工坊.弹幕[]`：弹幕列表（纯展示，可清空）

### B. 角色变量（角色系统里已有“当前状态”等字段）

- `角色.当前状态`：空闲/工坊中/休息中/逃跑中/加班中/…（用你角色系统已有字段）

> 说明：疲劳只作为“本单过程中的上限机制”。如果订单结算时疲劳没有达到上限，则不把疲劳留到下次订单里。

---

## 2) 订单库（可接取订单）字段清单

每条订单（订单库项）建议最少包含：

- `订单id`：系统生成稳定 id
- `工种`：冶炼/制药/改装
- `标题`
- `说明`
- `标签[]`

系统补全字段：

- `订单时长秒`：60~300 完全随机
- `基础金币`：系统随机
- `偏好`：
  - `偏好属性[]`（如 技巧/谨慎/智慧）
  - `偏好阈值`（如 >=3）
  - `满足偏好时的开局倍速加成`（如 +5%~+20%）

---

## 3) 进行中订单（运行态）字段清单（极简版）

> 只保留“必须落盘才能跨会话继续算”的内容。

每条进行中订单建议字段：

- `订单id`
- `角色id`
- `开始时间戳`（只需要这一个时间戳）
- `是否暂停`（如果需要暂停功能）
- `暂停累计秒`（暂停/恢复时把已经走过的“真实秒”累加进来；可选）

进度与结算关键字段：

- `进度秒`：已积累的“进度秒”（会被 tick 随机增减）
- `订单时长秒`
- `基础金币`

倍率字段（可选，优先不存，实时算）：

- `开局倍速`：订单开始时算一次（也可以不存，重新算；但涉及随机就需要存）
- `车间倍速`：不建议存（动态由“当前在工坊工作的人”实时算）

加班/失败相关：

- `加班中`：布尔（加班允许进度 > 100%）

疲劳相关：

- `订单内疲劳`：整数（只存在于订单运行态；订单完成后若未到上限则清空）

---

## 4) 弹幕（纯展示）字段清单

- `工坊.弹幕[]`：字符串数组即可（或者 `{text, color}`）

---

## 5) 清空机制（很重要）

### 5.1 弹幕清空

- **玩家手动清空**：点击按钮把 `工坊.弹幕` 置空
- **自动清空**：当 `工坊.进行中订单` 为空（所有订单完成/停止/失败）时，自动清空 `工坊.弹幕`

### 5.2 订单完成/失败后的清理

当某条订单从进行中结束时：

- 从 `工坊.进行中订单[]` 移除该条
- 将金币按进度条比例结算入账
- 疲劳：
  - 订单内计算 `订单内疲劳`
  - 若达到阈值则把 `角色当前状态 = 休息中`
  - 若未达到阈值则不保留（等价于清空，不写回角色）
- 更新 `角色.当前状态`：
  - 成功/中断结算：回到 空闲（或若疲劳到阈值则改为 休息中）
  - 逃班/事故失败：改为 逃跑中（或你定义的失败态）

### 5.3 角色状态如何清除（不使用时间戳）

- 角色状态由玩家在“角色管理界面”手动清空/复位（你已明确这个交互入口）。

---

## 6) 刷新订单（你指定：手动刷新 + 消耗金币）

- 行为：玩家点击“刷新订单”
- 消耗：扣除金币（与工坊等级相关）
- 效果：清空订单库并请求第二 API 生成新的文案字段，再由系统补全数值

建议清理：

- 刷新订单**不影响进行中订单**（避免玩家用刷新去刷进行中结果）
- 刷新前可选择：保留 `工坊.弹幕`（等工坊没活时自动清）
