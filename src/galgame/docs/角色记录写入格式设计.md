# 角色记录写入格式设计

本文档定义各玩法模块向角色 `记录[]` 字段追加日志的格式规范。

**前置文档**：`docs/角色系统详细设计.md` §1.2（记录层）、`docs/玩法-角色与派遣规划.md` §2.4

---

## 1. 记录条目的通用结构

每条记录的固定字段：

```yaml
- 时间: 时间戳（毫秒）
  类型: 派遣 | 工坊 | 通讯 | 其他
  内容: ""  # 格式由各玩法模块自定义
```

> `内容` 字段由各玩法模块自行组织，可以是纯文本，也可以包含结构化摘要（系统用 JSON 字符串存储）。

---

## 2. 写入时机

| 玩法 | 写入时机 | 由谁触发 |
|---|---|---|
| 废土行路 | 结算完成时（`triggerSettlement` 中） | dispatch 模块 |
| 工坊 v2 | 订单结束（成功/失败/中断）时 | workshop 模块 |

### 3.2 写入代码位置

在 `settlement.ts` 的 `triggerSettlement` 中，结算完成后写入：

```typescript
// settlement.ts
async function triggerSettlement(type: SettlementType, context: SettlementContext): Promise<DispatchRun> {
  // ... 结算逻辑 ...

  // 写入角色记录
  const role = getRole(context.roleId);
  if (role) {
    const logEntry = {
      时间: Date.now(),
      类型: '派遣' as const,
      内容: JSON.stringify({
        title: `【派遣】${context.location}`,
        result: type === 'success' ? '成功抵达' : type === 'forced' ? '被迫撤离' : '取消',
        location: context.location,
        route: context.route,
        gold: rewards.gold,
        souvenirs: rewards.souvenirCount,
        hpChange: context.stats.hp - context.stats.maxHp,
        sanityChange: context.stats.sanity - context.stats.maxSanity,
        eventCount: context.eventLog.length,
        battleCount: context.battleReward.lootCount > 0 ? context.eventLog.filter(e => /* 是战斗 */).length : 0,
      }),
    };

    // 追加到角色的记录数组
    role.记录.push(logEntry);
    updateRole(role);  // 写回聊天变量
  }

  // ... 后续逻辑 ...
}
```

### 4.2 写入代码位置

在工坊 tick 引擎的订单结算处：

```typescript
// workshopEngine.ts - 订单结算时
function settleOrder(orderRun: OrderRun, reason: 'complete' | 'interrupt' | 'fatigue' | 'escape'): void {
  const role = getRole(orderRun.角色id);
  if (role) {
    const logEntry = {
      时间: Date.now(),
      类型: '工坊' as const,
      内容: JSON.stringify({
        title: `【工坊】${orderRun.订单标题}`,
        result: reason === 'complete' ? '完成' : reason === 'interrupt' ? '中断' : reason === 'fatigue' ? '疲劳退出' : '逃班',
        workType: orderRun.工种,
        orderId: orderRun.订单id,
        gold: calculatedGold,
        progressRatio: orderRun.进度秒 / orderRun.订单时长秒,
        fatigue: orderRun.订单内疲劳,
        durationSec: Date.now() / 1000 - orderRun.开始时间戳,
        overtime: orderRun.加班中,
      }),
    };

    role.记录.push(logEntry);
    updateRole(role);
  }
}
```

## 6. 通用追加函数

封装一个通用写入函数，供所有模块调用：

```typescript
/**
 * 向角色追加一条记录
 * @param roleId - 角色 ID
 * @param type - 记录类型
 * @param content - 内容（建议传 JSON 字符串，便于后续解析）
 * @param title - 可选标题（用于面板展示）
 */
export function appendRoleLog(
  roleId: string,
  type: '派遣' | '工坊' | '其他',
  content: string,
  title?: string,
): void {
  const role = getRole(roleId);
  if (!role) {
    console.warn(`[roleLog] 角色 ${roleId} 不存在，无法写入记录`);
    return;
  }

  if (!role.记录) role.记录 = [];

  role.记录.push({
    时间: Date.now(),
    类型: type,
    内容: title ? `${title}：${content}` : content,
  });

  // 限制记录数量（最多保留最近 100 条）
  if (role.记录.length > 100) {
    role.记录 = role.记录.slice(-100);
  }

  // 写回聊天变量
  updateRole(role);
}
```

## 7. 记录的面板展示

角色管理面板中展示记录时，按 `类型` 分组，按 `时间` 倒序：

```typescript
// 角色管理面板 - 按类型分组展示记录
const groupedLogs = computed(() => {
  const groups: Record<string, typeof logs.value> = {};
  for (const log of logs.value) {
    const key = log.类型;
    if (!groups[key]) groups[key] = [];
    groups[key].push(log);
  }
  return groups;
});
```

## 8. 各模块记录对比

| 维度 | 废土行路 | 工坊 v2 |
|---|---|---|
| 类型值 | `派遣` | `工坊` |
| 写入时机 | 结算时 | 订单结束时 |
| 内容结构 | JSON（固定字段） | JSON（固定字段） |
| 核心数据 | 金币、纪念品、HP/Sanity 变化 | 金币、完成度、疲劳 |
| 生成方式 | 系统计算 | 系统计算 |
