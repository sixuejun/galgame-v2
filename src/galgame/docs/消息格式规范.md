# 消息格式规范（v1 强约束）

本文档定义 `src/galgame`（v1）视觉小说界面所支持的消息格式。

**重要：本规范是 v1 的硬协议（strict mode）**：
- assistant 消息必须遵守该格式，才能被 VN 主舞台显示。
- 不符合规范的消息会被视为“无 VN 内容”（不显示或只显示在酒馆原生楼层）。

- 设计目标见：[设计文档](./设计文档.md)

## 1. 总览

一条完整的 assistant 消息由三部分组成：

- `<content>...</content>`：VN 主舞台显示内容（必需）
- `<dm>...</dm>`：弹幕（可选）
- `<background>...</background>` / `<cg>...</cg>`：生图标签（可选）

示例：

```
<content>
[[character||角色名：白娅||场景：教室||台词：今天天气真好呢~]]
[[narration||旁白：她走进了教室]]
[[choice||去图书馆||去食堂]]
</content>

<dm>好可爱|这句我喜欢|别刀我</dm>

<background>
title###教室###
image###classroom, daylight, window###
</background>
```

## 2. 内容容器：`<content>`

### 2.1 规则

- assistant 消息**必须**包含 `<content>...</content>`。
- VN 主舞台**只解析并展示** `<content>` 内的内容。
- `<content>` 外的文本不会显示在 VN 主舞台（但可能用于弹幕/生图/玩法提取）。

### 2.2 解析约束

- `<content>` 内允许包含：
  - `[[...]]` 格式化块
  - 纯文本（视为旁白 narration）
- `<content>` 内的换行允许存在，并可作为“拆 block”的依据（由解析器实现）。

---

## 3. 块语法：`[[type||...]]`

### 3.1 基本结构

- 所有块以 `[[` 开始，以 `]]` 结束。
- `type` 为块类型（不区分大小写）。
- `||` 为字段分隔符。

### 3.2 字段形式

字段支持以下两种形态混用：

- 键值对：`键：值` 或 `键:值`
- choice 选项：直接写选项文本（见 choice 节）

---

## 4. 对话块：`character`

### 4.1 基本格式

```
[[character||角色名：xxx||场景：xxx||台词：xxx]]
```

### 4.2 字段

| 字段    | 键名（同义）      | 说明                        |
| ------- | ----------------- | --------------------------- |
| 角色名  | `角色名` / `角色` | 显示名称                    |
| 场景    | `场景`            | 背景场景名                  |
| 动作    | `动作`            | Live2D 动作关键词           |
| 表情    | `表情`            | Live2D 表情关键词           |
| CG 场景 | `CG场景`          | CG 场景名（优先级高于场景） |
| 台词    | `台词`            | 对话文本                    |

---

## 5. 叙述块：`narration`

### 5.1 基本格式

```
[[narration||旁白：她走进了教室]]
```

### 5.2 字段

| 字段 | 键名   | 说明           |
| ---- | ------ | -------------- |
| 场景 | `场景` | 可选，设置背景 |
| 旁白 | `旁白` | 叙述文本       |

---

## 6. 黑屏转场：`blacktext`

### 6.1 基本格式

```
[[blacktext||黑屏文字：xxx]]
```

### 6.2 兼容字段名

黑屏文字支持以下键名，按优先级匹配：

- `黑屏文字`
- `台词内容`
- `台词`
- `文字`
- `text`

---

## 7. 选择框：`choice`

### 7.1 基本格式

```
[[choice||选项1||选项2||选项3]]
```

### 7.2 带标签格式

```
[[choice||选项1：去图书馆||选项2：去食堂||选项3：自由输入]]
```

### 7.3 约束

- 选项文本内部不应包含 `||`。
- 若存在“自由输入”选项，应统一写作：`自由输入`（便于 UI 识别）。

---

## 8. 弹幕：`<dm>`

### 8.1 基本格式

```
<dm>弹幕1|弹幕2|弹幕3</dm>
```

### 8.2 约束

- 以 `|` 分隔弹幕条目
- 不建议在弹幕内包含 `|`

---

## 9. 生图标签：`<background>`/`<cg>`

### 9.1 背景标签

```
<background>
title###教室###
image###classroom, daylight, window###
</background>
```

### 9.2 CG 标签

```
<cg>
title###教室CG###
image###close-up, dramatic lighting###
</cg>
```

### 9.3 兼容性（重要）

- `image###...###` 中间的 `...` 就是提示词内容（建议英文逗号分隔，必要时可在括号里写中文细节）。
- v1 解析器同时兼容旧写法：`<image>...</image>` 等价于 `<cg>...</cg>`。

### 9.4 约束

- `title###...###` 与 `image###...###` 必须成对出现
- `image` 的内容建议为英文 prompt，逗号分隔

### 9.5 自动生图触发时机

带有图像标签的楼层会在以下三个时机自动触发生图请求：

| 时机                 | 触发位置                                                      |
| -------------------- | ------------------------------------------------------------- |
| 界面初始化           | `loadAllDialogues()` 完成后，若最新楼层含图像标签则立刻触发   |
| AI 生成新楼层        | `appendNewMessage()` 解析完成后，若该楼层含图像标签则立刻触发 |
| 楼层被编辑/回滚/重试 | `updateDialogueUnit()` 重新解析完成后，若含图像标签则立刻触发 |

> 前提：设置中「生图总开关」+ 对应类型开关（背景生成 / CG 生成）均已开启。

### 9.6 重新生图面板的自动填充

点击卡牌队列中心的重新生成按钮时：

1. 优先在**当前正在看的楼层**的 `imageTags` 中，用当前 block 的 `场景` 与 tag 的 `title` 做 fuzzyMatch，找到匹配的 tag 并取其 `prompt` 预填到弹窗。
2. 未找到时，回退从卡牌队列末尾取最近一张同类型图片的 `prompt`。

这意味着：如果在当前楼层的 `<background>` / `<cg>` 块中写了 `title###末日之梦###`，当你在观看 `场景：末日之梦` 的 narration 或 character 块时，点击重新生成会自动填入对应的提示词。

### 9.7 场景 ↔ 图片绑定（相册）

每张图片都可以被赋予一个 `title`（场景名），实现"场景 → 图片"的持久化绑定。

#### 绑定存储

绑定数据存储在**聊天变量** `vn_scene_bindings` 中，结构为：

```json
{
  "末日之梦": { "imageData": "data:image/png;base64,...", "type": "background", "timestamp": 1748512000 },
  "教室": { "imageData": "data:image/png;base64,...", "type": "cg", "timestamp": 1748513000 }
}
```

图片本体（base64）直接存在聊天变量里，不依赖卡牌队列，即使队列溢出也不会丢失。每个聊天独立存储，换聊天不串。

#### 绑定方式

| 操作 | 触发位置 | 说明 |
|------|----------|------|
| 导入图片自动绑定 | 重新生成面板「导入图片」按钮 | 导入时自动以当前 `场景` 为 title 写入绑定 |
| 手动绑定（绑定到场景） | 点击卡牌队列中的卡牌 | 以当前场景名为 title 写入绑定并展示到舞台，旧绑定被清除 |
| 相册替换 | 相册大图 → 编辑标题 → 指向新场景 | 后一次覆盖前一次 |

#### 卡牌队列行为

- **生图完成的图片**：只进入卡牌队列，**不会自动上舞台**
- **未绑定的图片**：无 title（或 title 与当前场景不匹配），不会自动展示到舞台
- **「确认插入」**：仅将选中的图片移入卡牌队列，**不写绑定**，玩家可在队列中预览和切换
- **离开卡牌队列且未绑定的图片**：会被完全丢弃

#### 场景切换时的展示优先级

当 `processImageTagBlocks` 处理图像标签时：

1. 聊天变量中有当前场景名绑定 → 从绑定取图片（插入队列并展示）
2. 队列中有相同 prompt 的图 → 复用（若 title 匹配则上舞台）
3. 无可复用图 → 发请求生图
4. 什么都没有 → 显示默认加载背景图

#### 相册

重新生成面板左下角「相册」按钮打开独立相册弹窗：

- 分 **背景** / **CG** 两页 tab，显示所有已绑定图片的缩略图 + title
- 点击缩略图 → 大图预览
- 大图下可执行：**编辑标题** / **替换图片（本地）** / **导入网络图片** / **插入卡牌队列** / **删除绑定**

## 10. 兼容性与流式容错

### 10.1 严格模式声明

v1 采用严格模式：assistant 消息缺少 `<content>` 将被视为无 VN 内容。

### 10.2 流式容错原则

生成过程中可能出现“半截标签/半截块”，解析器必须遵循：

- 只解析已闭合的 `[[...]]`
- 只解析已闭合的 `<dm>...</dm>` / `<background>...</background>` / `<cg>...</cg>`
- 未闭合内容应被忽略，等待后续 token 补全

该原则用于避免流式解析抛异常导致 UI 中断。
