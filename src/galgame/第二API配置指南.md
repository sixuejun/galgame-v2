# 第二 API 配置指南

> 末日报纸风 Galgame 第二 API 系统完整使用手册

**版本**: 3.0
**最后更新**: 2026-05-27

---

## 这份文档讲什么

这份文档介绍"第二 API"是什么、怎么配置、以及它驱动了哪些游戏功能。文档面向普通玩家，不要求你懂代码。

---

## 一、什么是第二 API

### 基本概念

第二 API 是一个**独立于主 AI 的备用接口**。你可以把它理解为游戏里的"后台助手"——它专门负责各种辅助任务，而主 AI 专心负责生成剧情对话。

### 第二 API 和主 API 的区别

| 对比项 | 主 API（剧情生成） | 第二 API（辅助任务） |
|--------|------------------|-------------------|
| 谁使用 | 酒馆主对话系统 | 游戏内部各种功能 |
| 负责什么 | 角色台词、旁白、剧情分支 | 弹幕、商店商品、生图标签、废土行路事件等 |
| 配置位置 | 酒馆主界面 | 游戏内设置面板 |
| 模型选择 | 通常用高质量模型 | 可用便宜模型（节省成本） |
| 是否必须 | 必须配置，否则无法对话 | 可选，不配置则相关功能不可用 |

### 为什么需要第二 API

1. **省钱**：辅助任务用便宜模型（如 GPT-3.5），主 AI 用好模型
2. **互不干扰**：弹幕生成不会拖慢剧情生成
3. **灵活配置**：不同任务可以共用同一个 API，各自使用不同的提示词
4. **可选择性使用**：不配置第二 API 也能玩，但部分功能（如弹幕、商店）将不可用

## 二、第二 API 支持哪些任务

配置好第二 API 后，以下功能才可使用：

| 任务名称 | 功能说明 | 是否必须配置第二 API |
|----------|----------|-------------------|
| **弹幕生成** | AI 生成评论弹幕，显示在屏幕上方 | 可选（设置中可关闭） |
| **生图标签生成** | AI 生成图片提示词，配合生图插件生成背景/CG | 可选（设置中可关闭） |
| **商店商品生成** | 每次刷新商店时 AI 生成 4 个随机商品 | 可选（不配置则无法刷新商店） |
| **废土行路事件生成** | 废土行路中 AI 预生成格子事件 | 可选（不配置则使用内置事件池） |
| **情报交换（猜谜）** | 与 AI 进行猜谜游戏 | 可选（不配置则无法玩猜谜） |
| **末世通讯（系统聊天）** | 与多个系统人格对话 | 可选（不配置则无法使用） |

## 三、配置步骤（详细图解）

### 步骤 1：打开设置面板

在游戏界面中，点击右上角的**齿轮图标**（设置按钮），打开设置面板。

### 步骤 2：找到第二 API 配置区域

在设置面板中向下滚动，找到"**API 配置**"区域（有服务器图标）。

### 步骤 3：填写基础配置

#### 3.1 接口地址（API URL）

在第一个输入框中填写 API 的接口地址：

- **OpenAI 官方**：`https://api.openai.com/v1`
- **其他兼容服务**：`https://你的服务商地址/v1`

> **注意**：地址末尾不要有 `/`，必须使用 HTTPS。

#### 3.2 API 密钥（API Key）

在第二个输入框中粘贴你的 API 密钥（通常以 `sk-` 开头）。

> **注意**：密钥是敏感信息，输入后会被隐藏显示。

#### 3.3 模型名称

有两种方式选择模型：

- **方式一（手动输入）**：直接在输入框中输入模型名称，例如 `gpt-3.5-turbo`、`gpt-4` 等。
- **方式二（自动拉取）**：点击"**拉取模型**"按钮，等待几秒后从下拉框中选择。

> **注意**：如果拉取失败，说明该 API 不支持模型列表接口，只能手动输入。常用模型参考：
> - `gpt-3.5-turbo`（便宜、快速，适合辅助任务）
> - `gpt-4`（质量高，较慢，较贵）
> - `gpt-4-turbo`（性价比之选）

#### 3.4 使用的预设

从下拉框中选择一个预设（Preset）。预设决定了 AI 的提示词格式。

> **重要**：预设需要在酒馆中预先创建。选择预设后，API 请求仍使用上方配置的第二 API 地址和密钥，但提示词内容来自预设文件。

### 步骤 4：测试连接

填写完基础配置后，点击"**测试连接**"按钮：

- 显示"**连接成功**"→ 配置正确，可以继续
- 显示"**连接失败**"→ 检查接口地址和密钥

### 步骤 5：高级参数（可选）

| 参数 | 作用 | 建议值 |
|------|------|--------|
| **流式输出** | 是否实时显示生成内容 | 建议关闭（后台任务不需要流式） |
| **温度（Temperature）** | 控制输出随机性（0=确定，2=极随机） | 0.7（平衡） |
| **最大回复长度** | 单次回复最多生成多少内容 | 弹幕 200、商店 300、聊天 1000 |
| **Top P** | 核采样范围 | 保持默认值 0.9 |
| **Top K** | 候选词数量 | 保持默认值 40 |

### 步骤 6：配置任务分配

在第二 API 配置区域底部，点击"**API 任务分配与生成历史**"按钮。

每个任务有三个选项：

- **主 API**：使用酒馆主界面配置的 API（通常质量高但成本高）
- **第二 API**：使用第二 API 配置（便宜、快速）
   - **禁用**：不执行该任务

> **建议**：弹幕、生图标签、商店商品建议使用"第二 API"，节省成本。

### 步骤 7：保存

所有配置**自动保存**，关闭设置面板后立即生效。

## 四、预设系统详解（EJS 语法）

### 什么是预设

预设（Preset）是一个文本文件，里面包含了 AI 生成各种辅助内容时使用的提示词。预设通过 **EJS 语法**实现"一个预设管理所有任务"——同一个预设文件，通过判断当前是哪个任务，自动切换到对应的提示词。

### EJS 是什么

EJS 是一种模板语言。它的核心只有两条规则：

- `<% if (条件) { %>` — 如果满足条件，执行里面的内容
- `<% } %>` — 结束判断

### 任务控制变量

系统会在调用第二 API 前，自动设置一些变量（True/False 开关）来告诉预设"当前是哪个任务"：

| 变量名 | 为 true 时表示 |
|--------|---------------|
| `vn_task_danmaku` | 当前任务是"弹幕生成" |
| `vn_task_imageGen` | 当前任务是"生图标签生成" |
| `vn_task_shop` | 当前任务是"商店商品生成" |
| `vn_task_boardGameEvent` | 当前任务是"废土行路事件生成" |

预设中用 `getvar('变量名')` 来读取这些值。

### 预设示例

以下是一个完整的预设模板示例：

```
你是一个末日废土风格的辅助 AI。根据任务类型提供相应的内容生成服务。

<%# 任务 1：弹幕生成 %>
<% if (getvar('vn_task_danmaku') && !getvar('vn_task_imageGen')) { %>

根据以下剧情内容，生成 3-5 条简短有趣的弹幕评论。
要求：
- 每行一条弹幕
- 每条不超过 20 字
- 风格多样（吐槽、感叹、疑问等）
- 符合末日废土世界观

<% } %>

<%# 任务 2：生图标签生成 %>
<% if (getvar('vn_task_imageGen') && !getvar('vn_task_danmaku')) { %>

根据场景描述生成适合的图片标签。
要求：
- 使用英文单词或短语，用逗号分隔
- 不超过 50 个词
- 包含：场景类型、环境、氛围、风格

<% } %>

<%# 任务 3：弹幕和生图合并（同时需要两者时） %>
<% if (getvar('vn_task_danmaku') && getvar('vn_task_imageGen')) { %>

请同时完成两个任务：
1. 生成 3-5 条弹幕评论（每行一条，不超过 20 字）
2. 生成图片标签（最后一行，格式：IMAGE_TAG: 英文标签）

<% } %>

<%# 任务 4：商店商品生成 %>
<% if (getvar('vn_task_shop')) { %>

生成 4 个末日风格的商品，每行格式：商品名|效果描述|价格（20-150 的整数）
商品名简短（2-6 字），效果描述简洁（5-15 字）

<% } %>

<%# 任务 5：废土行路事件生成 %>
<% if (getvar('vn_task_boardGameEvent')) { %>

根据事件类型和倾向生成一个事件，返回 JSON 格式：
{
  "title": "事件标题",
  "description": "氛围描写",
  "cards": [
    {"title": "选项1", "description": "描述", "effect": "效果", "tendency": "positive/negative/neutral", "hp": 0, "sanity": 0}
  ]
}

<% } %>
```

### 如何在酒馆中创建预设

1. 打开酒馆主界面
2. 找到"预设管理"或"Presets"相关设置
3. 创建新预设，粘贴上述模板内容
4. 在游戏设置中填写预设名称并选中

## 五、各任务的工作流程和输出格式

### 任务 1：弹幕生成

**触发时机**：AI 生成完一段剧情后（`GENERATION_ENDED` 事件）

**输入**：剧情文本（`<content>` 标签内的对话内容）

**输出格式**：每行一条弹幕，共 3-5 行，例如：

```
这剧情太刀了
前方高能预警
心疼主角一秒
卧槽反转了
```

**在游戏中发生了什么**：
1. AI 生成剧情完成
2. 系统提取 `<content>` 标签内的文本
3. 调用第二 API 生成弹幕
4. 弹幕以 100-500ms 随机间隔依次从屏幕右侧飘入
5. 每条弹幕完整飘出屏幕后消失

---

### 任务 2：生图标签生成

**触发时机**：AI 生成完一段剧情，且消息中包含场景变化标记

**输入**：剧情文本

**输出格式**：一行英文标签，逗号分隔，例如：

```
background, post-apocalyptic, wasteland, ruins, abandoned newspaper office, dusty, dim lighting, cinematic
```

**在游戏中发生了什么**：
1. AI 生成剧情完成
2. 系统检测消息中是否有 `[[character||...||场景：xxx]]` 或 `[[character||...||CG场景：xxx]]` 标记
3. 根据标记类型决定生成背景图还是 CG 图
4. 调用第二 API 生成图片标签
5. 将标签发送给外部生图插件
6. 生图插件生成图片后显示在屏幕上
7. 图片同时存入扇形卡牌队列

---

### 任务 3：弹幕和生图合并调用

**触发时机**：同时满足弹幕和生图条件，且两者都使用第二 API

**优势**：只调用一次 API，减少等待时间，节省费用

**输出格式**：弹幕行在前，最后一行为图片标签：

```
这剧情太刀了
前方高能预警
心疼主角一秒
IMAGE_TAG: background, post-apocalyptic, wasteland, ruins
```

> 系统自动识别 `IMAGE_TAG:` 或 `生图标签:` 开头的行作为图片标签，其余作为弹幕。

---

### 任务 4：商店商品生成

**触发时机**：玩家在商店模块中点击"刷新商店"按钮

**输入**：无（只用预设中的提示词）

**输出格式**：每行一个商品，格式为 `商品名|效果描述|价格`：

```
破旧绷带|恢复少量生命|30
生锈罐头|恢复饱食度|50
旧报纸碎片|可能包含线索|80
煤油灯|照亮黑暗区域|120
```

**在游戏中发生了什么**：
1. 玩家点击"刷新商店"
2. 扣除刷新费用（基础 50 金币 + 按持有金币比例的手续费）
3. 调用第二 API 生成 4 个商品
4. 显示在商店界面，玩家可以购买
5. 购买后物品直接进入背包

---

### 任务 5：废土行路事件生成

**触发时机**：废土行路模块中，玩家走到事件格子时

**输入**：当前场景描述 + 事件类型（encounter 遭遇 / trap 陷阱 / fortune 意外之喜）+ 事件倾向

**输出格式**：JSON 格式的事件数据，例如：

```json
{
  "title": "废墟中的发现",
  "description": "你在一堆废墟中发现了闪闪发光的东西...",
  "cards": [
    {"title": "仔细搜查", "description": "小心翼翼地搜索每个角落", "effect": "可能会有收获", "tendency": "positive", "hp": 0, "sanity": -5},
    {"title": "快速通过", "description": "这里太危险了，赶紧离开", "effect": "安全第一", "tendency": "neutral", "hp": 0, "sanity": 0},
    {"title": "大声呼喊", "description": "也许这里还有其他人", "effect": "可能引来敌人或同伴", "tendency": "negative", "hp": -10, "sanity": 5}
  ]
}
```

**在游戏中发生了什么**：
1. 玩家走到事件格子
2. 系统检查是否已有预生成的事件
3. 如果没有，调用第二 API 实时生成
4. 如果 API 失败，自动降级使用内置事件池
5. 显示事件卡牌，玩家选择一个选项
6. 选项触发后应用 hp/sanity 等效果

---

### 任务 6：情报交换（猜谜）

**触发时机**：玩家在"情报交换"模块中输入谜底和第一条提示后

**提示词构造**：不使用预设，由代码直接构造，包含角色设定、猜谜规则、对话历史

**输出格式**：AI 的猜测回复（纯文本）

**在游戏中发生了什么**：
1. 玩家输入谜底（本地保存，不发送）
2. 玩家输入第一条提示，开始游戏
3. 玩家继续提供提示，AI 不断猜测
4. 如果 AI 回复中包含谜底 → 游戏胜利，奖励金币（50 + 轮数 × 20）
5. 玩家也可以随时放弃（不结算金币）

---

### 任务 7：末世通讯（系统聊天）

**触发时机**：玩家在"末世通讯"模块中选择联系人并发送消息

**提示词构造**：不使用预设，由代码直接构造，包含人格设定和对话历史

**支持的功能**：
- **@ 引用**：在输入框旁点击 @ 按钮，输入楼层号（如 `3` 或 `1-5`）引用历史剧情作为上下文
- **Prompt 调试**：点击眼睛图标查看实际发送给 AI 的完整提示词

**在游戏中发生了什么**：
1. 玩家选择联系人人格（系统 01 / 啊哈 / 啾啾 / 阿P）
2. 玩家输入消息发送
3. 如果有 @ 引用，系统获取对应楼层的消息内容注入到提示词中
4. 调用第二 API 生成回复
5. 回复显示在聊天界面

## 六、故障排查

### 问题 1：连接失败

**可能原因**：
- 接口地址拼写错误
- API 密钥错误或过期
- 网络无法访问该地址
- API 服务商服务器宕机

**解决方法**：
1. 确认接口地址末尾没有多余的 `/`
2. 确认使用 HTTPS
3. 尝试在浏览器中直接访问接口地址
4. 检查密钥是否正确、是否过期

### 问题 2：模型列表拉取失败

**可能原因**：该 API 不支持 `/models` 接口

**解决方法**：手动输入模型名称（常用模型名在本文档"步骤 3.3"中有列出）

### 问题 3：请求超时

**可能原因**：网络慢、API 服务响应慢

**解决方法**：第二 API 有 30 秒超时和 2 次自动重试，等待自动重试即可。如频繁超时，考虑换一个更稳定的 API 服务商。

### 问题 4：功能没有反应

**排查顺序**：
1. 确认第二 API 状态是"可用"（不是"未配置"）
2. 确认该任务的"任务分配"设置为"第二 API"而不是"禁用"
3. 检查功能对应的开关是否已开启（如弹幕开关）
4. 查看浏览器控制台（F12）中的日志信息

### 问题 5：生成内容质量差

**解决方法**：
1. 优化预设中的提示词指令，给出更清晰的格式要求
2. 提高温度参数（0.8-0.9 适合创意任务）
3. 增大最大回复长度（避免内容被截断）
4. 尝试更换模型（如 GPT-4 明显优于 GPT-3.5）

## 七、世界书自动控制（进阶）

### 什么是世界书自动控制

世界书条目可以设置"目标 API"属性：
- `main`：只发送给主 API
- `second`：只发送给第二 API
- `both`：同时发送给两者

开启"自动控制"后，当你在设置中开关弹幕或生图功能时，对应的世界书条目会自动启用或禁用，无需手动管理。

### 配置方法

在世界书管理面板中，找到相关条目，勾选"自动控制"，并设置关联功能（弹幕/生图）。

## 八、技术参数参考

### 温度参数推荐值

| 任务 | 推荐温度 | 说明 |
|------|---------|------|
| 弹幕生成 | 0.9 | 需要创意和多样性 |
| 商店商品 | 0.8 | 需要一定随机性 |
| 生图标签 | 0.5 | 需要稳定性，避免标签跑偏 |
| 系统聊天 | 0.7 | 平衡 |
| 猜谜回复 | 0.7 | 平衡 |

### 最大回复长度推荐值

| 任务 | 推荐值 | 说明 |
|------|--------|------|
| 弹幕生成 | 200 | 3-5 条短弹幕 |
| 生图标签 | 100 | 英文标签约 50 词 |
| 商店商品 | 300 | 4 个商品 |
| 系统聊天 | 1000 | 对话可能较长 |
| 废土行路事件 | 800 | JSON 格式较长 |
